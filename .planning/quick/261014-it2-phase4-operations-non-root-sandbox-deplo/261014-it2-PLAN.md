- L1 Code: /opt/courtview/releases/<UTC ts YYYYmmddTHHMMSSZ>/ (root:root, dirs 0755, files 0644) and /opt/courtview/current -> releases/<ts> (relative symlink, flipped atomically with ln -sfn to current.tmp then mv -T). Keep the newest 3 releases plus current and previous; a failed release is renamed <ts>.failed and pruned by the same rule. Each release holds courtview.py, courtview.html, web/, cv_*.py, unit files, courtview-backup.pub.asc, requirements.in/.txt, and is precompiled as root with python3 -m compileall -q (the service sets PYTHONDONTWRITEBYTECODE=1 because /opt is read-only to it).
- L2 Data: /var/lib/courtview via StateDirectory=courtview, StateDirectoryMode=0700, owner courtview:courtview. Holds courtview_cache.db(+wal/shm), access.log(.1-.5), status/ (0755, files 0644 as today), backups/ (0700, .gpg 0600). One base constant COURTVIEW_DATA_DIR (env override, default /var/lib/courtview) drives DB_PATH, ACCESS_LOG_PATH, STATUS_DIR and the backup dir; existing per-path env overrides keep precedence so tests are unaffected.
- L3 Secrets: source files stay where they are (/root/.courtview_token, /root/.courtview_hmac_key, both 0600 root). courtview.service uses LoadCredential=token:/root/.courtview_token and LoadCredential=hmac_key:/root/.courtview_hmac_key. Code resolves each path as: explicit env (COURTVIEW_TOKEN_PATH / COURTVIEW_HMAC_KEY_PATH) > $CREDENTIALS_DIRECTORY/<name> > legacy /root default. Credentials are copied at start, so rotation = atomic rewrite of /root/.courtview_token then systemctl restart courtview (always safe here). _read_token's last-good logic stays as is.
- L4 Status for labs: /root/projects/courtview/status becomes a symlink to /var/lib/courtview/status. The paths labs reads (/root/projects/courtview/status/availability.json and payments.json, field last_ok) keep working unchanged; labs runs as root so /var/lib/courtview being 0700 is fine. Zero labs change; nothing to announce before deploy. /root/projects/courtview remains as a dir holding only that symlink plus a one-line README naming the new layout.
- L5 Notifier state: root-only /var/lib/courtview-notify (StateDirectory=courtview-notify in the root notifier and recovery units, mode 0700) holds unit_failure_state.json(+.lock) and the alert outbox. Deliberately NOT inside /var/lib/courtview: the sandboxed courtview user owns that dir and could otherwise tamper with root-read notifier state. This is "the new data dir" for the notifier; state the deviation in the summary.
- L6 Recovery trigger redesign: drop ExecStartPost systemd-run. New templated root units courtview-recovery@.service (oneshot, runs cv_notify_fail.py --check-recovery %i) and courtview-recovery@.timer (OnBootSec=2min, OnUnitActiveSec=1min, AccuracySec=15s, WantedBy=timers.target; deploy enables courtview-recovery@courtview.timer). The root notifier arms it (systemctl start courtview-recovery@<unit>.timer) whenever it opens an incident or queues an outbox entry. The check keeps today's rules (incident open, unit active >= 60 s, flock, one silent green per incident) and, when no incident is open and the outbox is empty, disarms itself (systemctl stop courtview-recovery@<unit>.timer). Result: no per-minute journal noise while healthy, survives a reboot mid-incident (enabled timer fires at boot), and the non-root service needs no systemd privilege. Templating lets the drill use a throwaway unit.
- L7 Backup runs as User=courtview (least privilege: it only reads the DB it owns, writes /var/lib/courtview/backups, reads the 0644 public key from /opt/courtview/current; gpg uses a temp homedir under PrivateTmp). Same sandbox as the service minus network (RestrictAddressFamilies=AF_UNIX).
- L8 notify-telegram@.service keeps its name (no other unit on the RPi uses it, verified 2026-10-14: only courtview.service references it). It stays root, reads the Telegram token via LoadCredential=telegram_token:/root/.telegram_token, and runs /opt/courtview/current/cv_notify_fail.py.
- L9 Dependencies: requirements.in holds the top-level names (curl-cffi, flask, gunicorn); requirements.txt holds the pinned closure (name==version, one per line, header comment with the upgrade procedure). cv_closure.py is the resolver currently embedded in deploy.sh, moved to a file so deploy and the upgrade procedure share it.
- L10 pip-audit: never auto-installed at deploy time (an unpinned install during deploy is itself a supply-chain risk). Missing pip-audit = BLOCK with the install hint.
